# 从零开始用 AI 设计项目

这是我学习用 AI 设计和实现项目的记录。起点是一个很具体的问题：当我只知道“想做一个用户反馈系统”，却不知道该选什么架构、语言或技术栈时，应该怎样开始？

我的做法是先说清用户、目标和验收结果，再请 AI 协助调查、拆解和比较方案。架构与技术栈服务于需求；重要的业务取舍由我确认。先做通一条完整功能，再根据测试和实际使用继续调整。

## 从这里开始

- [新项目从想法到上线：AI 协作设计流程](docs/新项目设计流程.md)：按项目规模选择梳理深度，逐步完成需求、设计、实现和验证。
- [第一次复盘：以前没有先选架构](docs/第一次复盘-以前没有先选架构.md)：如实记录过去的做法，并从已有项目中找下一步该验证什么。
- [ChronoDraft 案例：从保存版本理解现有设计](projects/chronodraft/保存与恢复的设计复盘.md)：沿真实代码追踪一条完整功能，区分源码事实、事后理解和待验证的体验。
- [项目实践记录模板](projects/README.md)：以后每做一个项目，记录当时的问题、选型依据、验证结果和复盘。

## 我想记录什么

这个仓库记录学习过程，不把 AI 给出的答案直接当成结论。每次实践尽量留下：

1. 最初想解决什么问题，哪些地方我还不懂。
2. AI 给了哪些建议，我查了什么资料、做了什么比较。
3. 我最终选择了什么，为什么，放弃了什么。
4. 做出来后怎样验证，哪些判断需要修正。

当前先放方法、模板和基于公开源码的复盘。后续再补充实际试用与改进结果。
