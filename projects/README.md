# 项目实践记录

这里会放真实项目的设计和复盘。每个项目可以新建一个文件夹，复制下面的模板记录。只写实际知道的事；没有记录或证据时，直接写「未记录」或「待验证」。

第一个案例：[ChronoDraft：从保存版本理解现有设计](chronodraft/保存与恢复的设计复盘.md)。

## 记录模板

新项目在动手前先填「目标与验收」「约束与范围」「方案与决定」；做完后补上实现和验证。复盘旧项目时，不要把今天推测的选型理由写成当时做过的决定。小脚本只需写清输入、输出和验收方式。

```markdown
# 项目名称

- 记录日期：
- 记录类型：新项目设计 / 旧项目复盘
- 对照版本：仓库链接、分支与提交 SHA；尚未建仓库则写「待建立」
- 当前阶段：设计中 / 已实现 / 已验证

## 1. 目标与验收

- 谁遇到了什么问题？最重要的一条用户流程是什么？
- 第一版做到什么算完成？正常、边界和失败时分别应有什么结果？

## 2. 约束与范围

- 平台、时间、预算、已有经验、数据和安全要求是什么？哪些还未知？
- 第一版做什么、暂缓什么？哪些业务结果需要我确认？

## 3. 方案与决定

- 当时实际考虑过哪些方案？依据、代价与决定是什么？没有记录就写「未记录」。
- 架构、语言和技术栈怎样服务于目标？关键取舍由谁确认？
- 事后才理解的理由或 AI 给出的推测，单独标为「事后分析」，不冒充原决策。

## 4. 实现与证据

- 主要职责和数据流是什么？链接到对应的公开代码或文档。
- 验证了什么？写明测试命令与结果、真实试用反馈；未做的写「待验证」。
- 每条结论注明依据：源码确认 / 测试通过 / 真实试用 / 推断 / 待验证。

## 5. 复盘与下一步

- 哪些判断得到证实，哪些需要修正？下一步最小行动是什么？
- 什么实际情况出现时，才重新评估暂缓的功能或架构？
```
